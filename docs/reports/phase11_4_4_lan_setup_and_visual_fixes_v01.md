# Phase 11.4.4：联机开局流程（身份 → 选将）与视觉修复

本阶段处理四件事，全部来自真实双开使用的反馈：

1. 联机局 UI 偏挤；
2. 身份局开局应当**先告诉每个人自己的身份**（与单机一致）；
3. 然后**选择武将**（与单机一致）；
4. 卡牌动画"有很多白色"。

## 一、UI 间距（看起来"挤在一起"）

设计空间是 1600×900，而底部三段（提示条 / 座位状态条 / 手牌）在早期版本里
已经贴到底边：提示条与状态条之间只有 8px，状态条与手牌之间 42px，手牌底部
只剩 10px。中央战场却有 364px 高，其中大片是空的。

调整（`src/ui/layout.py`）：

| 区域 | 原来 | 现在 |
| --- | --- | --- |
| 中央战场 | 176‥540（364 高） | 176‥506（330 高） |
| 提示条 | 546‥630（84 高） | 512‥608（**96 高**，放得下两行） |
| 座位状态条 | 638‥700 | 624‥688（与提示条间隔 **16**，原 8） |
| 手牌 | 742‥890 | 728‥876（与状态条间隔 **40**，原 42） |

配套改动：

* `prompt.draw`：标题 / 正文在 96 高的条里上下留白重新分布（18 / 50）；
* `judge.rect`：判定面板中心从屏幕高 0.42 提到 0.385——否则它会压住上移后的
  提示条（这条有测试盯着）；
* 客户端的本地提示（"已提交，等待房主结算…"）从"提示条上方"移到**手牌下方**：
  原来它和提示条叠在一起，正是"挤"的观感来源之一。

## 二、联机身份展示（与单机同一套屏）

联机现在是两段式开局，与单机的"身份揭晓 → 选将"完全对齐：

```
HostMatch.start()
 ├─ Game.begin_networked_setup()      建座位 + 发身份（不发牌、不开局）
 ├─ 每个远程玩家收到 IDENTITY_ASSIGN  只含**他自己**的身份（+ 主公名）
 └─ 房主本地进入 identity_reveal 场景  ← 单机同一个屏
        ↓ 双方都点「继续」
     IDENTITY_READY / host_identity_confirmed()
        ↓
 └─ 每个真人收到 GENERAL_CANDIDATES   互斥候选（每人 3 个，不重复）
        ↓ 各自选一个
     GENERAL_PICKED / host_general_picked()
        ↓ 所有人选完
 └─ Game.finish_networked_setup()     发牌 → 开局规则 → 首行动
```

界面**一行都没有重画**：远程玩家看的是单机的 `IdentityRevealScreen` 与
`GeneralSelectScreen`，只是数据来自网络（`src/ui/lan_setup.py` 把
`IDENTITY_ASSIGN` / `GENERAL_CANDIDATES` 装进一个最小适配器 `LanSetupGame`）。
联机里选将屏关掉了"随机 / 返回"两个按钮——候选由房主给定，那两个退路没有意义。

身份保密不变：`IDENTITY_ASSIGN` 只带收件人自己的身份；别人的身份既不在视图里，
也不在任何一条消息里（测试逐条检查原始载荷）。

## 三、联机选将

* 候选**互斥**：房主把武将池洗好后按真人顺序切片，每人 3 个互不重叠
  （否则两名真人可能选到同一个武将）。
* 选择受校验：不在候选里的 `general_id` 一律忽略（防越权 / 手滑）。
* 选将结果进 `Game.general_picks`，由 `_apply_opening_rules` 在分配武将时优先采用：
  真人拿到自己选的，AI 从剩下的池子里不重复抽取。
* 联机的自由混战没有身份可看、也没有武将池要选，直接进牌桌（沿用旧行为）。

## 四、"很多白色动画"的根因

`Renderer.draw_moving_card` 对**飞行中的牌一律画牌面**。而：

* 客户端"别人摸牌 / 拿走一张未知牌"用的是 `CardCache.placeholder()`——
  一张没有名字、没有花色的占位牌（`face_down=True`）。画出来就是一片空白；
* 房主侧更糟：AI 摸牌的动画直接画**真实牌面**，等于把别人摸到什么牌播给全场看。

修法：给 `MoveCardAction` 加纯表现的 `face_down` 标记，渲染时按它画牌背。

* `Game.queue_draw_cards`：只有**本机真人自己**的摸牌才画牌面；
* 客户端占位牌的 `face_down` 本来就为真，于是自动走牌背；
* 弃牌 / 出牌 / 响应照旧画牌面（那是公开信息）；
* 开局发牌用的 `draw_deal_flights` 本来就是牌背，不受影响。

顺带修掉了房主侧的**信息泄露**（AI 摸牌动画泄露手牌）。

## 六、等待反馈（真实双开反馈的修复）

真实双开时出现过"两边都卡住"：房主已经选了武将、点了「确认出战」却毫无反应，
提示还念着"看好了就点「继续」"；客户端那边停在身份屏，也没有任何"在等谁"的说明。

根因有二：

1. **房主的确认按钮会静默失效**：`host_general_picked` 只在"选将阶段"受理，
   而这时流程还停在**等对方确认身份**（`identity_done`），于是点击被直接丢掉，
   玩家看到的就是一局卡死的游戏。
   → 改成：先把选择记进 `host_pick`，等进入选将阶段**自动补交**
   （`_maybe_send_candidates` 里调 `_submit_host_pick`）。按钮再也不会有"点了没反应"。
2. **没有人说"在等谁"**：两边都只有"该做什么"的提示，没有"正在等谁"的提示。
   → `HostMatch.wait_message()` 输出「等待 远程玩家（确认身份）…」这类文案，
   房主的身份屏 / 选将屏每帧显示它；客户端在这一步做完之后也会把提示换成
   「已确认身份，等待房主下发候选武将…」/「已提交武将，等待其他玩家与房主开局…」。

对应测试：`SetupFlowTests` 里的
`test_host_can_pick_before_the_other_side_confirms`（预选要记住并自动补交）与
`test_wait_message_names_who_is_being_waited_on`（等待提示必须说清在等谁、等什么）。

## 七、牌桌"看着不大气"与间距（真实双开反馈）

真实双开时反馈"UI 一点都不大气""血量跟名字重叠""远程玩家和 AI 1 上下太挤"。
根源不是配色，而是**元素相对屏幕偏小、同一面板内的文字挤在一行**：

| 元素 | 原来 | 现在 |
| --- | --- | --- |
| 手牌 | 106×148 | **124×173** |
| 中央动作卡 | 104×144 | **132×184** |
| 牌堆 / 弃牌堆 | 50×70 | **64×90** |
| 座位卡高度 | 148 | 158（宽 252→264） |
| 侧座纵向间隔 | 16 | **42**（step 174→200） |
| 自己状态条 | 高 64 | **高 74**：名字 / 座次 / 血点各占一行（y 9 / 23 / 55，原来 6 / 14 / 42） |
| 悬停 / 选中的上浮 | 24 / 36 | 28 / 40（跟着放大） |

配套的位置修正：

* 牌堆与弃牌堆移到与动作卡同一条水平带（垂直居中于出牌位），中央形成一条主轴；
* "出牌阶段"标签从右下角移到**左下角**——牌堆放大后右下角必定压住弃牌堆；
* 判定面板中心从 0.385 再上移到 0.36，避免压住上移的提示条。

**重叠审计**：写了一个两两比对的检查（排除"容器与子元素"这种包含关系），
在 1600×900 / 1920×1080 / 1366×768 三种分辨率下检查提示条、手牌区、牌堆、
弃牌堆、动作卡、响应卡、三个按钮、技能键、四个装备槽与全部座位面板——
**没有真重叠**。相关约束已经由既有的布局测试（`test_all_resolutions_and_player_counts_are_clean`
等 206 项）持续把关。

顺带修了验收工具的一个坑：端口被上次没退干净的进程占用时，`run_local_lan_pair`
现在会**自动改用空闲端口**，而不是截出一张全黑的图。

## 九、剩余问题

1. **选将候选是房主洗好后切分的**，不接受玩家点"换一批"；单机也没有这个功能。
2. **没有选将超时**：某名真人一直不选，房主会停在选将屏等（不会有"自动帮选"）。
   真人掉线仍走原来的终止路径。
3. `lan_presentation_sync` 在机器负载高时偶现 1～2 项场景失配（重跑即过），
   是既有的脚手架时序脆弱。
