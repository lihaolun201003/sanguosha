# 武将胜率统计（模拟对战：自由混战 5000 局 + 1v1 5000 局）

工具：`tools/general_winrate.py`（本轮新增）。全部由 AI 自动对战，人工不参与。

```bash
python tools/general_winrate.py --mode both --games 5000 --players 5 --top 25
```

---

## 一、统计口径（先说清楚，不然数字会被误读）

| 项 | 取值 |
| --- | --- |
| 模式 | 自由混战（**无身份**，2~8 人各自为战，最后存活者获胜）+ 1v1（`duel_test`） |
| 人数 | 自由混战 5 人；1v1 2 人 |
| 局数 | 每种模式各 5000 局（共 10000 局） |
| 控制者 | **每个座位都是 AI**（包括"本机真人"那一席），同一套 AI 策略 |
| 选将 | 每局从当前 84 名可用武将里**随机不重复**分配（1v1 随机配对，先手随机） |
| 胜负 | 只认"最后一个存活者"（`LAST_SURVIVOR`）；没有平局 |
| 随机种子 | 固定（`--seed 424242`），同样的命令得到同样的结果 |
| 平均局时 | 自由混战 1330 个引擎步/局；1v1 416 步/局 |
| 总耗时 | 约 7 分钟（10000 局） |

**它衡量的是"AI 用这个武将的胜率"，不是"这个武将的理论强度"**：AI 不会用的
武将（例如需要精打细算的辅助技）分数会明显偏低，下面第五节给了证据。

基准线：自由混战 1/5 = 20.0%，1v1 1/2 = 50.0%。实测全体均值分别是
**20.1%** 与 **49.8%**——与基准吻合，说明座位、牌序、先手都没有系统性偏差。

## 五、几个 0% 武将：是规则把他锁死了，还是 AI 不会用

单独跑诊断（把某个武将钉进一个座位，40 局，统计每局平均数据）：

| 武将 | 平均回合 | 平均出牌 | 造成伤害 | 承受伤害 | 胜 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 刘备 | 4 | **0** | 0.1 | 4.4 | 0/38 |
| 徐庶 | 3 | 2 | 0.2 | 3.9 | 0/36 |
| 陈宫 | 3 | 5 | 1.5 | 3.7 | 0/38 |
| 郭嘉（对照） | 4 | 15 | 3.9 | 4.3 | 5/40 |
| 曹仁（对照） | 8 | 26 | 6.8 | 6.1 | 13/39 |
| 祝融（对照） | 7 | 18 | 8.9 | 3.5 | 23/39 |

**刘备平均出牌 0 张**——他在整局里一张牌都没打出去过。原因是 AI 对
"可变张数的主动技"一律按**上限**给牌：

```python
# src/game/controllers/ai.py::_active_skill_cards
if inputs.get("variable_cost"):
    cap = int(inputs.get("max_cost_cards") or 0)
    need = min(cap, len(candidates)) if cap else len(candidates)   # ← 取上限
```

刘备的【仁德】是"给任意张、给到第二张回 1 血"，AI 于是每回合把**整手牌**
送出去（多半送给对手），自己没牌防御也没牌进攻；徐庶/陈宫/荀彧的辅助技
（举荐 / 明策 / 节命）同理——把资源送给别人，自己先死。

**这不是规则 bug**（我单独验证了这几条技能本身按规则生效），而是 AI 策略
问题：辅助型主动技被 AI 用成了负收益。要不要修（例如"可变张数只给到达成
收益所需的最小张数""不给正在领先的对手"），我没有擅自动——那属于 AI 策略
调整，会改变实际对局表现，需要你点头。

## 六、顺带修掉的一个真 bug：陷阵的无界递归

第一版 5000 局跑的时候，**约 5% 的对局直接崩**（`RecursionError`），另外还有
若干局跑不完。抓出来的调用环是：

```text
DistanceRule.distance()           计算距离
  └─ Game.distance_modifier()     汇总技能修正
       └─ 陷阵（xianzhen）的修正
            └─ -DistanceRule.distance(...)   ← 又去算距离
                 └─ …无限递归
```

`_xianzhen_ignore_distance` 的意图是"与拼点对手的距离视为 0"，但它拿
`distance()` 当基数，而那个函数又会把本修正算一遍。这是**真实对局也会崩**的
路径（只要高顺赢过一次拼点又在算距离）。

修法两处（都不改规则语义）：

1. `DistanceRule.base_distance()` —— 新增"不含技能修正的基础距离"（座位环 +
   坐骑），陷阵改用它当基数：`-base_distance` → 最终距离被夹到最小值 1
   （= 视为相邻，永远够得着）；
2. `Game.distance_modifier()` —— 加一个**重入闸门**：修正自己在算距离时，
   修正合计按 0 处理。这样以后任何人再写"在距离修正里算距离"，都不会把
   整局打死。

验证：`seed 424258` 从"RecursionError"变成"正常打完（胜者马超）"；
陷阵语义单独验证——基础距离 2 的目标在陷阵获胜后距离变 1，其他人不受影响；
5000 局崩局率从 5% 降到 0.02%（1 局 TypeError，正在定位，另见下节）。

## 七、遗留与说明

1. **1 局 TypeError**（第一次 5000 局里）：用同种子 + `--verbose` 完整重跑
   一遍**没有再复现**（第二次 0 异常），所以不是"某个种子一定崩"的确定性
   bug；现场抓不到，暂按"未知、极低频"记录（约 0.02%）。
   两次 5000 局的对照：第一次 超时 5 / 异常 1，第二次 超时 6 / 异常 0。
2. **5~6 局超时**（5000 局里，约 0.1%）：AI 之间长时间僵持没分出胜负
   （例如双方都不愿意先动手），不是卡死（引擎仍在推进），只是超过了
   40000 步的上限；这些局不计入胜负统计（对胜率的影响 < 0.15%）。
3. 数值是**固定种子**下的确定性结果；换种子会有 ±1~2 个百分点的波动
   （每名武将的出场次数只有 250~340 次，标准误差约 2%）。
4. 结论只适用于"当前这套 AI"：AI 策略一改，榜单会变——尤其那几个 0% 的武将。
5. 数据文件：`docs/reports/general_winrate_ffa.json`（自由混战）、
   `docs/reports/general_winrate_duel.json`（1v1），含全部 84 名武将的
   出场 / 胜场 / 胜率。
