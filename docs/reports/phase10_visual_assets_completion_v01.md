## 1. 原 UI 资源结构

Phase 9 及以前，游戏界面**完全由代码绘制**，不存在任何外部图片：

| 元素 | 原实现 |
| --- | --- |
| 卡牌正面 | `ui/cards.py::_draw_face_content`：程序画底色 + 牌名 + 花色点数 |
| 卡牌背面 | `theme.card_back_surface()`：程序画暗红渐变 + 金框 + 菱形回纹 |
| 武将 | 圆形头像占位（姓氏首字）/ 选将界面的势力色条 + 头像圆 |
| 身份 | 纯文字（`你的身份：反贼`） |
| 装备区 | 几何图标（`draw_slot_icon`：短剑 / 盾牌 / 圆环）+ 名称 |
| 判定区 | 紫色小标签 + 单字（乐 / 粮 / 电） |

因此本阶段的工作是：**把一个纯代码绘制的界面，改造成以真实卡面为视觉主体、程序绘制为骨架与兜底的界面**，并且过程中不能改变任何规则行为。

## 2. Asset Registry 设计

新增 `src/ui/assets.py`（唯一新增的 UI 模块）。

核心约定：

- **路径只出现一次**：所有 `assets/` 路径集中在模块的映射表里；Renderer、Overlay、SeatPanel、CardWidget 一律不知道文件名。
- **稳定 ID → 素材**：`general:caocao`、`identity:rebel`、`card:SHA:fire`。ID 由 `general_id` / `Identity.value` / `Card.name + Card.nature` 生成，不依赖中文名或文件名猜测。
- **只读**：只从 `assets/` 读，缩放与适配全部在内存中完成，**不回写任何素材文件**。
- **不建立第二套游戏数据**：本模块只有"ID → 图像"，不含任何技能表、卡牌规则或身份规则。

映射规模：

| 资源 | 数量 | 说明 |
| --- | --- | --- |
| 武将牌 | 11 | 正式武将，`general_id → generals/cards/*.png` |
| 武将牌背 | 1 | `将牌.png` |
| 身份牌 | 4 | 主公 / 忠臣 / 反贼 / 内奸 |
| 游戏卡牌 | 43 | 基本牌 4 + 锦囊 15 + 装备 24（含 EX / 军争） |

两个真实的命名差异用**显式别名**处理（不是猜测）：

- `CIXIONG` 游戏名"雌雄双股剑" → 素材 `雌雄双剑.png`
- `QINGGANG` 游戏名"青釭剑" → 素材 `青钢剑.png`

`asset_inventory.json` 只在初始化时读一次，用于诊断（校验映射路径确实在索引里），不参与每帧运行。

## 3. Cache 设计

两层缓存，全部按资源 ID 索引：

| 层 | key | 生命周期 | 上限 |
| --- | --- | --- | --- |
| 原始 Surface | `asset_id` | 进程级永久 | 无（每个资源只有一个） |
| 缩放 Surface | `(asset_id, w, h)` | 进程级 LRU | 256 条 |

- 缩放统一走 `pygame.transform.smoothscale`，**每帧不会重复加载或重复缩放**。
- 窗口 resize 只增加新的尺寸条目，**不会清空原始资源**；超出上限时按 LRU 淘汰最旧的缩放结果。
- 加载失败 / 缺失的结果同样会被记住，不会反复重试或反复刷日志（每条只警告一次）。

实测（1920×1080，连续 120 帧，已预热）：

| 场景 | 平均帧耗时 | 帧内 磁盘加载 / 缩放 / 缓存命中 | 缩放缓存条目 |
| --- | --- | --- | --- |
| 2 人 | 3.49 ms（≈287 FPS 上限） | 8 / 8 / 1960 | 8 |
| 4 人 | 3.92 ms（≈255 FPS 上限） | 2 / 2 / 2950 | 10 |
| 8 人 | 4.34 ms（≈230 FPS 上限） | 5 / 6 / 4915 | 16 |

（60 FPS 的预算是 16.7 ms/帧。）长时间 UI smoke 累计 900 帧、6 次 resize 后：`loads=18, scales=65, hits=19746, missing=0`。

## 6. 游戏卡牌接入策略

接入点**唯一**：`ui/cards.py::draw_card`。所有手牌、桌面牌、弃牌堆、公共牌池、动画飞行牌都走这一个函数，因此不存在"漏改某处"的情况。

绘制顺序（自下而上）：

```
① 阴影 + 程序卡面底色      ← 图片没铺满时露出的就是这块底色
② 真实卡面（fit_contain）  ← 有素材且卡片够大时
③ disabled / dimmed 遮罩
④ 边框
⑤ 真实 suit / rank 徽标    ← 永远画在卡面之上
⑥ selected / candidate 状态边框  ← 永远在最上层，不会被图片盖掉
```

各区域：

| 区域 | 卡面 | 说明 |
| --- | --- | --- |
| 手牌 | ✅ | 106×148 设计尺寸，完整卡面 + 花色点数徽标 |
| 桌面中央牌 / 结算中的牌 | ✅ | 同手牌路径 |
| 弃牌堆顶牌 | ✅ | 同手牌路径 |
| 五谷 / 选牌公共池 | ✅ | 80×112，仍用真实卡面 |
| 装备区（自己） | ✅ | 62×50 槽内卡面缩略 + 底部半透明名字条，功能名不丢 |
| 装备区（其他座位） | ❌ | 槽内只有 18px 图标位——按"缩到 20px 根本看不清就继续用程序化装备条"的约定保留图标 |
| 判定区（自己 / 座位） | ✅ | 标签内嵌真实卡面极缩略（约 13×18）+ 原有单字，两者都在 |
| 牌堆 / 对手暗手牌 | ❌ | 素材库里**没有普通游戏牌背**，继续用程序绘制的牌背（没有拿武将牌背冒充） |

小卡阈值：宽 < 76 或高 < 104 的卡片退回程序绘制（名字 + 花色点数的紧凑排版），避免把卡面缩到不可辨认。

## 7. 花色点数一致性方案

**素材实况（已逐张实际查看确认）**：这套扫描图的卡面上**没有大面积的花色点数区域**。标准版 / EX 牌的花色标记位于角落且很小，军争牌基本只有属性图标（如【火杀】左上角的火焰）。

因此**不需要做遮罩**，方案直接采用"底图 + 数据层"：

```
扫描卡面（只作为美术底图）
    ↓
左上角绘制真实 suit + rank 徽标（半透明深色底衬 + 金色描边，保证在任何卡面上都可读）
```

- 花色符号用符号字体渲染（♠♥♣♦），点数用 `Card.rank` 原文。
- 颜色按 `card_color`（红 / 黑）取自既有主题色。
- 卡面缩到看不清时不计成本：小卡直接改用程序绘制，花色点数照常显示。
- `Card.suit` / `Card.rank` **一个字都没有被改动**：映射表只按 `Card.name` 取图，同一张牌的不同花色点数共用同一张底图。

实测证据（新增测试）：

- `card:SHA`（黑桃 7）与 `card:SHA`（红桃 9）解析到**同一个素材 ID**。
- 渲染这两张牌得到**不同像素**（证明差异来自被绘制的真实数据，而不是素材）。
- 实体牌与"无花色点数的虚拟牌"底图相同、渲染不同（证明徽标是被额外绘制上去的）。

## 8. Fallback

三层兜底，任何一层失效都不会影响运行：

| 失效场景 | 行为 |
| --- | --- |
| 资源文件不存在 | 该卡片 / 武将 / 身份退回程序绘制（骅骝就是这种情况，见第 12 节） |
| 文件损坏 / 不是图片 | `pygame.image.load` 异常被捕获 → 返回 `None` → 程序绘制 |
| 没有 display surface（dummy / headless） | 跳过 `convert_alpha()`，使用原始 Surface，测试环境照常工作 |
| 未收录的武将（第二批） | 选将界面画回原来的头像圆，仍可正常选中并开局 |

缺失只警告一次（`[assets] 素材缺失，退回程序绘制：card:HUALIU`），不会每帧刷屏。

## 13. 非阻断问题

1. **骅骝（HUALIU）没有素材**。素材库里马牌只有 6 张（赤兔 / 大宛 / 紫骍 / 绝影 / 的卢 / 爪黄飞电），骅骝不在其中。已确认这是素材缺口而非映射遗漏，运行时自动退回程序绘制；新增测试显式记录这一已知缺口。
2. **一处旧测试断言被更新**。`test_first_draw_relayouts_when_metrics_change` 原断言"选将卡片宽度 > 336"，这个 336 是**横向卡片时代**的设计基准。Phase 10 卡片改为竖版武将牌（420:572）后，宽度基准不再成立，已改写为"2560×1440 的卡片面积必须大于 1600×900"——保留了"布局随分辨率重算"的原意。该测试的其余断言（面板居中、卡片在屏内）未改动。
3. **横版素材在竖版卡位里留白**。`乐不思蜀` 与 `兵粮寸断` 是横版扫描图（436×320，对应延时锦囊的横置形态）。统一 contain 带来上下留白，换取的是**绝不变形**；如果后续希望它们铺满，需要单独定义横版卡位的排版规则。
4. **两张效果较弱的素材**：`无懈可击`（400×562，真彩色无 Alpha，不透明底）与 `绝影`（400×562，仅圆角透明）。都已按 contain 统一缩放并验证不破坏卡片尺寸，视觉上可接受，本阶段未做任何图像修复。
5. **装备名可能被省略**。自己区域装备槽只有 62×50，"青龙偃月刀"这类长名会显示为「青龙…」。装备卡的完整名称仍可在悬停 tooltip 里看到，因此未强行压缩字号。
6. **11 名武将全量显示时卡片偏小**。选将界面在"全量 11 名 + 1280×720"下卡片只有约 61px 宽；实际游戏流程只显示 3 名候选（卡片约 315×499），不受影响。这个全量路径主要用于测试与异常兜底。
7. **素材自带的 libpng 警告**。部分 PNG 带 `iCCP: known incorrect sRGB profile`，是素材文件自身的色彩配置声明，libpng 只提示不报错，不影响加载与显示。
8. **普通牌背仍然缺失**（素材阶段已记录）。牌堆与对手暗手牌继续使用程序绘制牌背，本阶段按要求未另找资源、也没有用武将牌背冒充。
