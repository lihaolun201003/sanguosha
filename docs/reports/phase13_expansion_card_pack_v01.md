### 逐张核对后确认的六个关键点

1. **张颌.png 是源文件名错字**：卡面印的是「张郃」（WEI 009、巧变、料敌机先）。
   目标 id 用 `zhanghe`，显示名「张郃」，映射在
   `src/ui/assets.py:EXPANSION_GENERAL_ASSETS` 里显式写明。
2. **徐庶 / 徐庶2 都是蜀**：两张卡的左上角势力标记都是「蜀」字。
   徐庶.png 是蓝色卡框但**标记仍是蜀**，不得据此判成魏；
   徐庶2.png 是红框。两张卡的技能名与正文逐字相同 → 规则上是同一名武将，
   因此登记成**同一武将的两张卡面**（`GENERAL_ALTERNATE_ASSETS`），
   而不是两名武将。
3. **钟会.png 的技能正文是空白**：卡面只印了技能名「同谋」「陷害」，
   正文面板没有任何文字（多种 OCR / 二值化方案交叉验证）。没有找到与之
   匹配的可信规则来源，**没有**擅自替换成【权计】/【自立】——
   条目保留在图鉴里，`implemented=False` 并写明原因。
4. **神将的「神」不在名字里**：8 张神将卡面只印武将本名（关羽 / 诸葛亮…），
   「神」是左上角的势力印玺。因此用 `version="神"` 把展示名变成
   「关羽（神）」，与标准版关羽、SP 关羽三者互相区分。
5. **SP008 是同一编号的两个形态**：`最强神话`（神势力 8 体力，马术+无双）与
   `暴怒的战神`（神势力 4 体力，马术/无双/修罗/神威/神戟），两张卡面都保留、
   都标 `test_only`：只能在 1v1 测试模式里显式选择，不进随机池，
   也与神将目录的【神吕布】完全分开。
6. **刘禅标记.png 不是武将牌**：它是配合【放权】的「额外回合」令标记
   （画面是吐舌头的刘禅 + 头顶「令」字菱形徽标），归入
   `assets/expansions/markers/liushan_marker.png`，不参与武将注册。

### 银月枪（SP010）

卡面：**【银月枪】**、装备 / 武器、**方块 Q**、**攻击范围 3**、
「在自己回合外，若打出一张黑色花色的牌，可立即指定攻击范围内的一名玩家
出一张[闪]，否则减一点体力。」

两个要核实的点都落在实现里（`src/game/equipment_skills/system.py`）：

* **时机是「回合外 + 打出（响应）」**，不是"使用"——因此订阅的是新增的
  `CARD_RESPONDED` 事件而不是 `CARD_USED`；
* **「减一点体力」是失去体力**，走 `Game.lose_hp` 而不是伤害流程：
  不触发受伤类技能、不吃防具与伤害加成，但体力降到 0 依然进入濒死。

牌堆里是 `weapon("YINYUEQIANG", 3, "diamond", "Q")`，开发牌堆 128 → 129 张。

## 四、为扩展包补齐的通用机制

全部做在**规则层**，核心流程不认任何具体武将（沿用既有架构约定）：

| 机制 | 位置 | 使用者 |
| --- | --- | --- |
| 拼点 | `skills/mechanics.py:PindianFlow` | 天义 / 驱虎 / 烈刃 / 陷阵 / 制霸 |
| 翻面 | `mechanics.flip_player` + `TurnMixin.start_turn` 跳过回合 | 据守 / 放逐 / 破军 / 神愤 / 归心 / 酒诗 / 悲歌 / 极略 |
| 觉醒技 | `mechanics.awaken`（减上限 → 回复 / 摸牌 → 永久获得技能） | 志继 / 魂姿 / 拜印 / 凿险 / 若愚(未实现) / 单骑 |
| 限定技 | `mechanics.consume_limited` / `limited_used` | 涅槃 / 乱武 / 业炎 |
| 标记 | `Player.marks`（**别人也要读**：武魂看谁持最多、暴虐看谁造成伤害） | 狂暴 / 忍戒 / 梦魇 / 田计数 |
| 武将牌上的牌区 | `Player.placed_cards`（田 / 不屈牌） | 屯田 / 不屈 |
| 技能获得 / 失去 | `gain_skill` / `lose_skill` / `lose_all_skills` | 极略 / 无前 / 伪帝 / 断肠 / 挥泪 |
| 额外回合 | `Game.queue_extra_turn` + `TurnMixin.start_next_turn` | 连破（放权未实现） |
| 伤害转移 | 改同一个 `DamageContext.target` | 天香 |
| 花色改写 | `ModifierKind.SUIT_AS` + `Game.card_suit` | 红颜（天香的红桃要求走同一查询） |
| 虚拟防具 | `ModifierKind.VIRTUAL_ARMOR` + `Game.has_armor` | 八阵（装备控制器不再直读 `equipment`） |
| 牌类别锁定 | `ModifierKind.CATEGORY_FORBIDDEN` + 发现层 / 强制弃牌 / AI 弃牌三处门控 | 鸡肋 |
| 锦囊伤害来源改写 | `ModifierKind.TRICK_SOURCE` + `Game.trick_source` | 祸首 |
| 锦囊使用距离改写 | `ModifierKind.TRICK_DISTANCE` + `CardEffect.distance_limit_for` | 断粮（距离 2） |
| 濒死救援禁令 | `ModifierKind.RESCUE_FORBIDDEN` + `DyingFlow._rescue_names_for` | 完杀 |
| 「不死」检查点 | `EventType.DYING_BEFORE_DEATH` | 不屈 |
| 【杀】目标规则动态化 | `CardEffect.target_rule_for` / `target_bounds_for` + `ShaEffect` 覆写 | 天义（+1 目标）/ 神戟（至多三名） |
| 【杀】无距离限制 | `ModifierKind.SLASH_DISTANCE_IGNORE` | 武神 |
| 【杀】禁用 | `ModifierKind.SLASH_FORBIDDEN` | 天义没赢 / 陷阵没赢 |
| 同花色多张转化（X 随局面变化） | `CardConversion.count_for` + `bounds()` | 龙魂（X = 当前体力） |

**新增的事件**（都是"一次通知、多条技能共用"的通用时机）：
`CARD_DISCARDED`（唯一弃牌出口）、`CARD_LOST`（失去牌但没进弃牌堆）、
`CARD_RESPONDED`（打出，与"使用"区分）、`SHA_DODGED`（杀被闪抵消）、
`HP_RECOVERED`（回复体力，带施治者）、`FLIPPED`、`DYING_BEFORE_DEATH`。

**交互式回合补发的阶段事件**：`TurnFlow.finish_interactive` 现在会补发
**弃牌阶段**与**结束阶段**的事件——此前真人 / AI 的真实对局里这两段不发事件，
据守 / 崩坏 / 琴音 / 狂风 / 大雾这类技能永远不会触发。

## 七、可用性过滤（统一入口）

新增 `Game.general_available(id, for_random=False)` /
`playable_generals()` / `playable_general_ids()` 作为**唯一**判断入口
（`GeneralDef.availability_for(mode_id)` + `random_eligible_for(mode_id)`），
下列入口全部改走它：

* 本地候选池（`selectable_generals`）、随机按钮、`roll_general_candidates`；
* `general_pool_ids()`——显式传进来的池子同样过滤，夹着非法 id 也不会进对局；
* AI 自动分配（`assign_generals`：显式指定与联机 picks 都要过一遍）；
* `confirm_general` 的隐式池；
* 联机权威端选将池（`HostMatch.general_pool()`）；
* 1v1 设置页的随机按钮与点选（`random_for` / `choose_general`）。

`test_only` 形态（SP008 两张吕布）：普通模式**任何入口**都拿不到，
在 1v1 测试模式里可以显式点选，但**随机按钮仍然抽不到**。

## 十、已知限制

* **被动触发的精确覆盖面**：【屯田】的"失去牌"覆盖弃牌与 `CARD_LOST`
  （被拿走 / 送出去），但"把牌放进自己的判定区 / 装备自己的牌"这类不在
  回合外发生的动作不参与；
* **鸡肋**的类别锁定覆盖"使用 / 打出"与两条强制弃牌路径（回合结束超限、
  AI 弃牌）；真人**手动**弃牌时该类别的手牌仍可被点选，这是 UI 选择层的
  既有实现，本轮未改；
* **神速 / 神速类的阶段改写**只影响本回合已排好的阶段表，不会凭空插入新阶段；
* 神将、SP008 这类高体力 / 高复杂度武将会让 AI 对局的回合数变长，
  `test_engine_v2_phase5_multiplayer` 的长局用例因此对随机种子更敏感
  （本轮的最终全量运行通过，但它在不同种子上本来就有波动）。
