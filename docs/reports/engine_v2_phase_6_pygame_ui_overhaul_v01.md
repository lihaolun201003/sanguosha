# Engine V2 Phase 6：Pygame 桌面版 UI 全面重制

报告日期：2026-09-19
范围：把 Phase 5 稳定的多人规则层之上的「开发调试界面」重构成正式桌面卡牌游戏观感。
技术栈不变：Python + Pygame，无 Web、无大型 GUI 框架、无外部美术资源。
规则层未被修改（仅新增只读 helper 与取消选择的 UI 状态）。

---

## 1. UI 重构前存在的问题

Phase 5 结束时界面能用，但明显是调试工具：

1. **配色是开发默认色**：桌面用饱和绿色 `(45, 105, 65)`，面板是浅灰 `(205, 205, 198)`，文字大面积纯白，缺少统一的视觉语言。
2. **座位面板是纯文本框**：AI 面板用五行 16px 文字堆出「座次 / HP / 手牌 / 武器 / 防具 / 判定」，没有头像区、没有血点、没有状态徽章，死亡只靠一行灰字。
3. **卡牌只是一个彩色圆角矩形 + 居中文字**：没有大类底色区分、没有类别标签、牌背是纯色块。
4. **没有悬停反馈**：手牌不会上浮，选中的牌与未选中的牌只有边框颜色差。
5. **手牌不做重叠**：手牌多时会一直压缩间距直到重叠成一团，且没有选中/悬停位移，最后几张牌难以点中。
6. **提示散落各处**：`game.message`、`game.response.prompt`、`choice` 弹窗、`pending_selection` 提示分别画在不同坐标，玩家要靠读文字和日志才能判断当前该做什么。
7. **按钮是裸矩形 + 默认字体**：没有 Hover、没有 Pressed、没有 Disabled，结束回合按钮在不能结束时直接隐藏。
8. **中央区域是碎的**：牌堆、弃牌堆、打出的牌、阶段文字、消息、日志分别固定在六个互不相干的坐标上，没有形成牌桌中心。
9. **Rename/删除遗留**：`draw_enemy`、`get_enemy_hand_rects`、`ENEMY_EQUIPMENT_RECTS` 等 1v1 时代坐标仍参与渲染；引擎动画落点（`constants.TABLE_CARD_RECT` 等）与渲染布局不一致，导致打出的牌飞到错误的位置。
10. **无动画**：除了引擎驱动的飞牌，没有任何伤害、回复、回合切换、判定的视觉反馈。

## 6. 手牌

`src/ui/cards.py` + `src/ui/player.py`：

- **真正的牌面**：类别底色（基本暖白 / 锦囊淡蓝灰 / 装备淡金）、内描边印刷感、左上角「花色 + 点数」（红桃方块用红色、黑桃梅花用深灰）、中央牌名、右下类别标签（装备显示「武器 / 防具 / +1 马 / -1 马」）。
- **重叠布局**：牌宽 88，可用宽 624。放得下时保持 10px 间隙，放不下时按 `(可用宽 − 牌宽) / (张数 − 1)` 计算步进，20 张与 30 张手牌都能完整落在手牌区内，且每张牌的花色与点数是可见的（实测步进 18～28px）。
- **悬停上浮**：鼠标进入牌的基础矩形或已抬起矩形（两者并集，避免抬起后鼠标脱离造成闪烁）时上浮 22px。
- **选中上浮**：已选中的牌（选牌流程 / 丈八素材）上浮 34px 并加金边。
- **不可用灰化**：`player.playable_hand_indices()` 逐张调用引擎注册的 `CardEffect.can_use` 探测（含目标合法性），不可用的牌加灰蒙层，亮度明显降低。
- **界面不复制规则**：灰化只读引擎结论，UI 内没有任何 `if card.name == ...` 分支；不在真人回合 / 有 Pending 时直接返回 `None`，不做任何灰化。

## 7. 装备区

- 真人与 AI 使用同一套槽位定义（武器 / 防具 / +1 马 / -1 马），无宝物体系。
- 槽位图标由 Pygame 几何绘制：武器=斜置短剑、防具=盾形轮廓、马=圆环加方向符，空槽为灰色。
- 真人装备槽显示卡名（超出 5 字截断），空槽显示「空」。
- 悬停真人装备弹出说明：牌名 + 花色点数 + 类型（如「装备牌 · 武器」）+ 攻击范围 + 牌面效果描述（读取 `card.description`），不硬编码规则文本。
- 悬停 AI 面板返回该角色可见的第一件装备，避免 8 人桌面为每个 AI 保留固定装备槽。

## 9. 中央牌桌

`src/ui/table.py`：

- **牌堆**：程序生成卡背 + 下方「牌堆」标签 + 剩余张数；摸牌时边框高亮脉冲。
- **弃牌堆**：显示最近进入弃牌堆的一张牌的面 + 「弃牌」+ 张数；弃牌时高亮脉冲。
- **当前打出的牌**：使用 / 响应中的牌落在中央展示位（`TABLE_CARD_RECT` / `RESPONSE_CARD_RECT`），并保留了引擎驱动的飞牌动画。
- **公共牌区**：五谷翻牌与「从其他角色区域选牌」的候选统一摊在中央上方，支持蓝框候选 / 黄框已选与点击。
- **阶段标签**：中央右下角小条显示当前阶段（准备 / 判定 / 摸牌 / 出牌 / 弃牌 / 结束）。
- **回合横幅**：回合开始时中央出现「AI 3 的回合」并淡出。
- **战报**：移到左下角，只保留最近 5 条、每条截断 13 字，不再抢占屏幕中心，也不遮挡任何座位。

## 10. Pending / Prompt

`src/ui/prompt.py` 用一份 `describe(game)` 把全部等待状态归一：

| 来源 | kind | 显示 |
|---|---|---|
| `game.response` | response | 「需要你的响应」+ 原始 prompt + 可用牌提示（内部名转中文：`TAO → 桃`） |
| `game.choice` | choice | 标题 + 描述（铁索连环 / 重装 / 装备技能二选一） |
| `game.pending_selection` | select | 原始 prompt + 「点击公共区 / 手牌 / 装备区完成选择」+ 「还需选择 N 张」 |
| `game.pending_target_selection` | target | 「请选择目标 / 请选择 1～2 个目标」+ 「已选择 x / y」 |
| `game.zhangba_selecting` | zhangba | 「丈八蛇矛」+ 「已选择 x / 2」 |
| `PendingRequest`（AI owner） | waiting | 「等待 AI 3 响应」+ 请求内容 |
| 真人出牌 / 弃牌阶段 | play / discard | 「出牌阶段」+ 操作提示 / 「请弃置 N 张手牌」 |
| 其它 | info | 「当前行动者 · 阶段」+ 引擎消息 |

显示时只占一条 60px 高的面板（在中央区与真人区之间），不遮挡任何座位、手牌或按钮。规则层没有新增任何 Pending 类型，全部是 presentation。

## 11. 动画

**与规则完全解耦**：动画不参与任何 Flow 的推进。`src/ui/fx.py` 只在 `EventDispatcher` 上订阅只读事件，用本地计时器播放表现：

| 事件 | 表现 | 时长 |
|---|---|---|
| `DAMAGE_APPLIED` | 座位红光 + 水平抖动 + `-N` 浮字 | 0.45s / 0.30s / 1.0s |
| `ATOM_AFTER` + `RecoverHpAtom` | 座位绿光 + `+N` 浮字 | 0.45s / 1.0s |
| `TURN_START` | 座位金光 + 中央「XX 的回合」 | 0.45s / 1.3s |
| `JUDGE_REVEALED` | 中央判定面板（牌面 + 结果） | 1.8s |
| `DEATH` | 「阵亡」浮字 + 座位灰化 | 1.0s（灰化为持续状态） |
| `CHAIN_STATE_CHANGED` | 「横置 / 重置」浮字 | 1.0s |
| `DYING_ENTERED` | 座位红光 + 「濒死」浮字 | 0.45s / 1.0s |
| `DrawCardsAtom` / 弃牌 `MoveCardAtom` | 牌堆 / 弃牌堆边框脉冲 | 0.5s |

出牌、摸牌、弃牌的**位移**沿用既有 `ActionQueue`（它是引擎 continuation 的一部分，本阶段未做任何语义改动），只把落点坐标对齐到新布局，并把动画时长控制在 0.28～0.32 秒。

## 15. UI 状态与 Engine 的边界

- **唯一真值来源**：HP、手牌、装备、判定区、座次、当前行动者、Pending 全部实时从 `Game` 读取，UI 不保存第二套状态。
- **UI 只保留表现状态**：hover 索引、按下按钮、浮动文字、闪光计时、判定横幅剩余时间。
- **几何唯一**：`TableLayout` 每帧构建一次，绘制与 `player_at_position` / `hand_index_at` / `public_rects` 共用同一批 `pygame.Rect`，不存在「面板移动了但点击还在旧位置」。
- **动画与规则解耦**：特效通过 `EventDispatcher.subscribe` 只读事件；引擎在任何动画播放中都不同步等待 UI。
- **规则不反向依赖 UI**：`src/ui/*` 单向依赖 `Game`；`main.py` 把点击翻译成既有 `Game` 入口（`player_use_card` / `end_player_turn` / `respond_with_card` / `select_pending_card` / `confirm_target_selection` …）。
- **可用性提示不复制规则**：灰化走 `CardEffect.can_use`，UI 内没有牌名判断。

## 19. 本阶段修掉的缺陷

### 19.1 顺手牵羊 / 过河拆桥 / 麒麟弓选不中对方装备（玩家实测发现）

**现象**：对只剩装备（手牌为 0）的角色使用顺手牵羊时，公共区明明摊开了那张装备牌，玩家点击却毫无反应，Prompt 一直停在「还需选择 1 张」，对局无法继续。

**根因**：引擎把「从其他角色区域选牌」的候选做成 `(card, key)` 二元组，`key` 是该牌所在装备槽（`weapon` / `armor` / 某一匹马）；`is_selection_candidate(card, key)` 也按 `key` 比对。但 Phase 5 的公共区点击只回传了卡牌、没有回传 `key`，于是 `key=None` 与候选的 `key="weapon"` 不匹配：

- `select_pending_card` 判定为「不是候选」，静默丢弃这次点击；
- 公共区的高亮同样按 `key=None` 判断，装备候选**连蓝框都不会出现**；
- 只有「对方还有手牌」时才能点到手牌候选（其 `key` 本来就是 `None`），所以这个问题在目标手牌非空时被掩盖。

**修复**：

```text
src/game/card_selection.py   + selection_pool_entries()  返回 [(card, key)]
src/ui/table.py              draw_pool 接收 entries，按 key 判断候选 / 已选
src/renderer.py              + get_pool_entries()，绘制与查询都用 entries
main.py                      公共区点击把 entries[index][1] 作为 key 回传
```

影响范围同时覆盖**顺手牵羊、过河拆桥、麒麟弓**三条使用同一选牌路径的牌。

**测试**：新增 5 项（`EquipmentPickTests`）——候选带槽位、绑定按钮后真正拿起武器、过河拆桥弃掉防具、手牌候选仍然 `key=None`、装备候选在公共区被高亮且在窗口内。

### 19.2 AI 回合偶发停滞

**现象**：`tools/multiplayer_smoke.py` 长局压测中，约每 150～250 局出现一次对局停住（AI 的回合停在出牌阶段，没有排队动作、没有等待中的 Pending）。

**根因分析**：AI 回合由 `ActionQueue` 的连续回调推进（出牌 → 结算 → 继续出牌 → 结束回合）。若某条异常路径（例如判定阶段闪电的「暂停 / 恢复」链在极端时序下提前结束）把这条链断开，`game` 会稳定停在「`phase=play` + 队列空 + 无等待输入」，主循环不知道该做什么。

该状态难以稳定复现（固定牌序 60 组与 500+ 局随机对局均未再次命中），因此本阶段采取**防御性修复**而非继续等待复现。

**修复**：`Game.update()` 增加回合守卫 `_guard_stalled_turn()`：

```text
条件：非 game_over + 场景为对局中 + 非 busy + 无 ActionQueue 动作
      + 无引擎 Pending / 无选牌 / 无目标选择 / 无响应 / 无二选一 / 无丈八选牌
      + 当前行动者是 AI 且存活 + 阶段为 play 或 discard
持续 40 帧（约 0.66 秒）后：记一条「（回合守卫）继续 XX 的回合」，收尾该回合并交给下一名存活角色。
```

守卫**不会**触碰真人回合、也不会在任何等待玩家输入的状态下触发（4 项测试覆盖这两个边界）。它在正常情况下永不满足条件，只在动作链真的断开时兜底。

**测试**：新增 4 项（`TurnStallGuardTests`）——断开时接回、真人回合不受影响、等待响应时不触发、引擎 Pending 打开时不触发。

**验证**：修复后 252 局随机长局压测异常 0（此前同规模曾出现 1 例）。

## 20. 节奏（速度）控制

玩家反馈「每次交互速度太快，来不及看清」，因此加入可调节奏。

### 20.1 引擎侧

```text
Game.speed                     当前倍率（默认 1.0）
Game.SPEED_STEPS = (0.5, 0.75, 1.0, 1.5, 2.0)
Game.set_speed / slower / faster / speed_index / speed_label
Game.update(dt)                → actions.update(dt * speed)
```

所有动画与等待都由 `dt * speed` 驱动，因此倍率同时作用于：飞牌、摸牌、弃牌、伤害与回复闪光、回合与判定横幅、以及引擎里既有的阶段停顿（回合开始 0.5 秒等）。倍率只缩放时间轴，不改变任何规则结算顺序。

AI 出牌之间新增 `AIController.CARD_PAUSE = 0.35` 秒的观察停顿，一个回合不会再在瞬间打完。

### 20.2 节奏模式（`Game.ai_pacing`）

AI 的 Pending 响应默认是同步完成的（一条结算链在一帧内跑完）。真实对局开启 `ai_pacing` 后，`GameEngine.present_or_auto_resolve` 会把 AI 的响应排进动作队列：

```text
WaitAction(AI_RESPONSE_PAUSE = 0.42s) → CallbackAction(AI 提交 GameAction)
```

于是南蛮 / 万箭 / 连环 / 求桃 / 无懈这类「连续多人结算」会按响应者逐个出现，而不是一瞬间全部结束。Flow 在排队期间本来就处于等待状态，延迟提交只是把「谁回应」交给动作队列驱动，**不改变任何规则判定**；停顿期间若对局结束，回调会清空等待中的请求。

默认值：`ai_pacing = False`（规则测试保持同步语义，断言可预测）。真实入口显式开启：

| 入口 | 设置 |
|---|---|
| `main.py`（真实游戏） | 开启 |
| `tools/multiplayer_smoke.py`（长局压测） | 开启 |
| `tools/ui_smoke.py`（dummy 交互流程） | 开启 |
| 单元测试 | 关闭（同步） |

### 20.3 界面控件

游戏内左上角常驻一个小控件（不与任何 2～8 人座位或手牌重叠）：

```text
┌──────────────┐
│   节奏 − / ＋ │
│  [−]  1×  [+]│
└──────────────┘
```

- 点击 `−` / `＋` 逐档调整；到达两端时对应按钮自动禁用。
- 键盘 `-` / `=`（主键盘与小键盘均可）同样可调。
- 设置在整个进程内保留：重新开始、返回主菜单都不会重置节奏。

### 20.4 实测节奏

`tools/pacing_measure.py` 统计「玩家结束回合 → 再次轮到玩家」在 60 FPS 下需要的帧数（3 种开局取平均）：

| 速度 | 平均帧数 | 约合真实时间 | 相对最慢档 |
|---|---|---|---|
| 0.5× | 3083 | 51.4 秒 | 1.00× |
| 0.75× | 2028 | 33.8 秒 | 1.52× |
| 1×（默认） | 1582 | 26.4 秒 | 1.95× |
| 1.5× | 1026 | 17.1 秒 | 3.00× |
| 2× | 781 | 13.0 秒 | 3.95× |

默认档比最慢档快约一倍，最快档比默认档快约一倍半，档位之间区分明显。

### 20.5 顺带修掉的健壮性问题

测量脚本对选牌类 Pending 误发 `PassPendingAction` 时，引擎会把它当成「放弃」并让五谷结算拿到空结果，最终以 `IndexError` 崩溃。现在 `GameEngine._pass_pending` 显式拒绝非「响应牌」类型的请求：

```python
if request.request_type is not PendingRequestType.RESPOND_CARD:
    raise ValueError("this PendingRequest cannot be answered with a pass: " + ...)
```

误用会立刻得到清晰错误，而不是在流程深处崩溃。新增 2 项契约测试（选牌请求拒绝 Pass、响应牌请求 Pass 正常）。
