# Phase 18：结算演出 / 技能提示 / 火攻交互

> 本轮不改规则，只解决"规则已经正确执行，但画面跟不上引擎推进"。
> 所有结论都来自真实引擎 + 真实 Renderer 的探针（脚本在 `.cache/phase18/`，
> 证据 JSON 在 `docs/reports/phase18_*.json`）。

## 1. 原来为什么会出现"判定没播完，人已经死了"

判定在这套架构里是**同步结算**的：`JudgeFlow` 翻出判定牌后，同一个调用栈里
立刻继续走 `JUDGE_RESULT` → 收尾 → 伤害原子 → 濒死 → 阵亡。引擎这样是对的
（网络与规则不该等动画），问题在表现层当时只有两处"压制"，都不管画面事件流：

| 机制 | 管什么 | 为什么不够 |
| --- | --- | --- |
| `ActionQueue.hold`（`JudgePanel.holds_actions`） | 压住**还没开始的动作**（实体牌移动） | 只管动作队列，`Effects` 的飘字 / 闪红 / 战报是事件回调里**直接**画的 |
| `JudgeGate` | 压住**真人输入**（谁能出牌 / 点得动） | 管的是"能不能操作"，不是"画什么" |

而 `JudgePanel.begin()` 只是**启动**了一个 4～6 秒的状态机；与此同时
`DAMAGE_APPLIED` → `show_damage`、`DYING_ENTERED` → `show_dying`、
`DEATH` → `show_death` 全都在同一帧直接执行了。于是玩家看到的是
"判定牌刚翻开，座位已经闪红、飘出 -3、写着阵亡"。

联网侧还多一层：客户端的状态来自**快照**（`GAME_VIEW_SNAPSHOT`，另一条消息），
它可能比 `GAME_EVENT` 更早把 `hp=0 / alive=false` 送到，于是连"座位变灰"
都会提前出现。

## 2. 最终怎么分离 authoritative state 与 presentation state

两条互不干扰的通道：

```text
权威状态（规则 / 网络 / 快照 / 决策 / 命中测试）
    ├─ 立刻更新：引擎继续跑，快照照常覆盖，客户端该能操作就操作
    └─ 渲染层直接读的对象一个都没换

表现状态（画面）
    └─ PresentationQueue（新，src/ui/storyboard.py）
         ├─ 演出按顺序消费：判定 → 技能 → 伤害 → 濒死 → 阵亡 → 下一回合
         └─ VisualLedger 视觉增量账本：
              显示体力 = 权威体力 − 还没轮到播的增减
              显示存活 = 权威存活 ∨ 还有未播完的伤害 / 濒死 / 阵亡演出
```

关键点是**账本不是缓存状态，而是"差值"**：快照把体力改成 0 之后，画面上
那道 `-3` 还挂在账上，`display_hp()` 返回 `0 - (-3) = 3`；伤害演出真正开始时
把这条增量释放掉，显示值自然回到权威值。因此

* 不需要缓存整份 Game（客户端也不缓存 ClientGameView）；
* 重连 / 重同步天然安全（账本永远是"权威 + 未播增量"）；
* 存档、AI、规则、网络协议一个字节都没动。

实测（`.cache/phase18/probe_judge.py` + `probe_lan.py`）：

```text
闪电命中（判定演出中间帧）
  画面体力 = 3      权威体力 = 0      ← 快照没有抢跳
  画面存活 = True   权威存活 = False  ← 死亡 UI 没有提前
  演出队列 = [judge, judge, …]  之后才是 damage / dying / death
```

## 3. 是否使用了统一 Presentation Queue

**是**，而且是唯一的一条：`src/ui/storyboard.py::PresentationQueue`。

* 房主侧：`Effects` 订阅引擎事件后**不再直接画**，改为 `present_*()` 排队；
* 客户端侧：`ui/client_fx` 的事件处理器调**同一个** `present_*()`；
* 队列自己一行都不画，只是"什么时候轮到谁"——真正画画的仍是既有
  `Effects.show_*` / `JudgePanel` / `SkillBanner`。

没有新造第二套动作系统：实体牌的移动仍在既有 `ActionQueue` 上（判定期间由
`JudgePanel.holds_actions` 压住，这一层原样保留）。

顺带因此自动获得的能力：

* **不被丢弃**：关键演出（判定 / 技能）在积压时优先保留（`MAX_PENDING=64`）；
* **合并**：连续两次同一个技能（锁定技反复触发）合并成一条，不刷屏；
* **同一次结算只播一次**：伤害在引擎里先是一条"失去体力"，两条演出都排队时
  后者把前者吃掉（与客户端 `_absorb_hp_lost` 同源）。

## 8. 火攻的新界面

┌──────────────────────────────────────────────┐
│                    火攻                       │
│           AI 2 · 对方已展示一张手牌            │
│                                              │
│  对方展示的牌              请选择你要弃置的牌   │
│   ┌────────┐               ▣高亮  ▢变暗  ▢变暗 │

## 10. 锁定技怎么避免疯狂重复弹窗

三道闸门，缺一不可：

1. **只在真的生效时发事件**：`EquipmentEventSkill` 的"规则集合"通知被关掉
   （`Skill.announces = False`）——它不是武将技能，名字（"装备锁定技"）对玩家
   没有意义，而且绑的是每次伤害计算 / 每次杀，弹出来就是刷屏；真正改变结果
   的锁定效果（仁王盾 / 藤甲 / 白银狮子 / 古锭刀）由规则自己发一条**带牌名与
   卡面说明**的通知。
2. **标记类变化不发技能提示**：暴怒 / 忍这类 `marks` 事件在下发与表现两侧
   都被过滤（实测弹窗数为 0）。
3. **队列层合并**：连续两条"同一个人的同一个技能"合并成一条，时长按重新计时
   延长一点，而不是排两条。

持续型 modifier（马术一类）不弹：它们不产生具体结算事件，本来就不会进队列。

## 11. LAN Host / Remote 是否都能看到别人的技能提示

都能。技能 / 判定 / 火攻展示 / 阶段跳过全部走既有的表现事件桥
（`PresentationBridge` → `GAME_EVENT`），并新增了两条：

* `phase_skipped`：带结论文本（"乐不思蜀 判定成功 · 跳过出牌阶段"）；
* `card_revealed`：带真实牌面（火攻展示，公开信息）。

技能事件补了 `kind_label` / `text` 两个可选字段，装备锁定技没有 `SkillDef`
也能显示类型与说明；武将技仍然只发 `skill_id`，类型与说明由**客户端本地技能表**
补齐（不让说明多走一趟网络）。

实测（`probe_lan.py`，真实 socket + 真实 Renderer）：

* 客户端收到 `skill` 事件并真的把技能提示面板画了出来（抓到
  `banner=仁王盾`，时长 2.02 秒 = 基准 × 本机倍率）；
* 客户端收到 `phase_skipped` 且文本正确；
* 火攻两阶段在客户端都拿得到 `reason` 与展示牌；
* 真实 main.py 双进程（`tools/run_local_lan_pair.py --capture`）两边退出码 0、
  客户端无渲染异常。

**不泄露**：技能事件只带技能 id / 名字 / 目标 id（既有的公开信息），
火攻展示牌是规则要求公开的牌；没有新增任何"把别人手牌发出去"的字段。

## 12. 后续 snapshot 是否还会覆盖正在播放的关键动画

**不会**（对"体力 / 存活"这两个最刺眼的量）：

* 客户端权威视图照常按 revision 更新（`probe_lan.py` 里
  `权威 hp=0` 的同时 `画面 hp=3`）；
* 画面值 = 权威值 − 未播增量（`VisualLedger`）；
* **濒死也预定"仍然按存活显示"**：濒死在规则上还没死（可以求桃），
  只盯"阵亡演出"的话，快照先把 `alive=false` 送达时座位会提前变灰——
  这个坑在 LAN 探针里被真实抓到了（一次 FAIL），修掉后才稳定。

其余量（手牌数、装备、判定区、弃牌堆）仍然是"快照即真相"：它们没有
"必须先看完某段演出"的语义，延迟反而会让玩家疑惑。演出本身的顺序由队列
保证，与快照无关。

## 13. ViewSpeed 是否仍然客户端独立

**是**。整条演出队列由**本机**速度驱动：

```text
座主：Game.speed            → PresentationQueue.update(dt × speed / 0.75)
游客：RemoteGameView.speed  → 同上（各自的对象，互不同步）
```

* 不进权威状态、不进快照 / revision / DecisionRequest / 网络载荷
  （Phase 17.2 的 13 项审计仍然全过，包含"网络载荷里完全没有速度字段"）；
* 慢档只让这台机器更长，快档更短；
* **最短可读时间**：判定来源 / 判定牌 / 判定结果每个阶段都有绝对下限
  （`ui/judge.py::MIN_STAGE`），极速档也不会"闪一下"；
* 实测客户端把速度调到 1.5 之后房主仍是 0.75，房主侧结算与动画不受影响。

## 15. 尚未解决的问题

1. **火攻"无同花色"时使用者看不到"我没有可弃的牌"的专门界面**：
   流程直接结束，只有一条提示条（`card_revealed` 事件）。规则正确，但如果
   玩家希望看到一个明确的"你无法弃置"面板，还需要一个新的表现事件。
2. **判定牌被改判后左侧"判定来源"仍展示原始来源**：改判信息写在右列文字里
   （"司马懿 发动【鬼才】改判（共 1 次）/ 原判定：…"），没有把"从什么换成
   什么"画成两张牌并排。
3. **客人自己发动技能时，自己的提示不比别人短**：需求里提到"本地发动者可
   适当缩短"，当前统一 2 秒（一致性更好，但确实多占了本地玩家一点时间）。
4. **队列积压**：极端连续结算（8 人南蛮 + 多个触发技）下队列可能落后引擎
   数秒。上限与丢弃策略已就位（非关键演出可丢），但没有"跳过未播演出"的
   手动入口。
5. **手牌数 / 弃牌堆仍然即时更新**：这两项没有演出语义，故意不做延迟；
   如果你希望"摸牌动画播完再变数字"，那是另一轮的事。
