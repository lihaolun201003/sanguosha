## 1. 箭头动画架构

**没有新建动画系统**：箭头完全挂在既有的 `src/ui/fx.py`（Effects 订阅引擎事件、自己维护计时器）和 Renderer 的绘制流程上。

数据来源全部是引擎事件，**没有在 UI 里枚举卡名**：

| 来源 | 提供 |
| --- | --- |
| `CARD_USED`（已有） | `source` + `payload["targets"]` + `payload["card"]` |
| `SKILL_TRIGGERED`（**新增 targets 字段**） | `source` + `payload["targets"]` |

`SKILL_TRIGGERED` 的 targets 是在 `skills/activation.py` 里加的**纯表现数据**（"谁对谁发动了技能"），不参与任何规则判定。

流程：

```
引擎结算 → CARD_USED(source, targets, card)
            ↓
Effects._on_card_used → add_arrow(source, targets, color=按牌的属性)
            ↓
TargetArrow 列表（多目标带 delay 错开）
            ↓
Renderer → table.draw_action_arrows()（画在座位之上）
```

- **颜色只按牌的属性**（红牌暖色 / 黑牌冷蓝 / 装备金色），不认识具体牌名。
- **无目标牌不画箭头**：桃、无中生有、装备自己都不产生假箭头。
- **两端裁到座位面板边缘**（`TargetArrow.endpoints`），所以箭头不会遮住面板里的血量 / 身份 / 手牌数。
- **纯几何绘制**：宽线 + 两层"与桌面底色混合"的近似外光 + 三角形箭头，不建 Surface、不用 shader、无高斯模糊。
- **多目标逐个出现**：`delay = index × target_step`，南蛮入侵 7 人局实测延迟 0 / 0.34 / 0.68 / 1.02…，不会七根一起铺满屏幕。
- **顺序沿用引擎给定的座次**，UI 不重排 targets。

## 2. 动画速度调整

新增集中的 `src/ui/fx.py::FXTiming`，所有表现层时长从它取，不再散落 magic number：

| 动作 | Phase 10 | Phase 10.2 |
| --- | --- | --- |
| 中央出牌展示 | ~0.45 | **0.62** |
| 单目标箭头 | — | **0.95** |
| 多目标间隔 | — | **0.34** |
| 伤害 / 治疗浮字 | 1.00 | **0.85** |
| 座位闪光 | 0.45 | **0.62** |
| 判定牌展示 | 1.80 | **1.05**（并新增 judge_swap = 0.50 给改判前后） |

引擎侧的**动作队列**也整体放慢：`Game.DEFAULT_SPEED` 从 `1.0` → **`0.75`**，档位扩展为 `(0.4, 0.55, 0.75, 1.0, 1.5, 2.0)`。真人仍可用键盘 −/＋ 继续调整。

表现层档位另有 `ANIMATION_SPEED_PRESETS`（slow 1.30 / normal 1.0 / fast 0.70），可用 `fx.set_speed_preset()` 切换。

结果：杀 → 等待闪 → 出闪 → 继续这一串终于"不用盯战报也能跟上"；无懈链也不再一口气跑完（每个 Pending 都有自己的排队节奏）。

## 3. 通用 Engine 新能力

| 能力 | 实现位置 | 说明 |
| --- | --- | --- |
| **多响应需求** | `ModifierKind.RESPONSE_COUNT` + `Game.response_required_count()` | 无双只需声明"多要一张"，杀的结算按数字循环要牌 |
| **目标合法性** | `ModifierKind.TARGET_FORBIDDEN` + `target_candidates(..., card=None)` | 空城 / 谦逊只声明"谁能被指定"，杀的合法性、UI 高亮、AI 决策共用同一份过滤 |
| **伤害加成** | `ModifierKind.DAMAGE_DEALT` + `DamageFlow` | 裸衣只声明"+1"，伤害流程统一汇总 |
| **主公技** | `SkillDef.is_lord_skill` + `SkillManager.bind_general` | 只有"身份模式 + 本人是主公"才绑定；FFA 永不给 |
| **可变费用** | `ActiveSkillSpec.variable_cost` | 制衡 / 仁德可选任意张；同时修好了引擎里"可变费用技能选不了牌"的缺陷 |
| **交牌给目标** | `ActiveSkillSpec.transfer_cards` | 仁德的费用牌进目标手牌而不是弃牌堆 |
| **回合外视为技** | `CardConversion.available` | 急救只在回合外可把红牌当桃 |
| **手牌清空** | 复用 `ATOM_AFTER` + `MoveCardAtom` | 连营不在 `use_card()` 里判断，弃牌 / 被顺 / 被拆 / 交出都会触发 |
| **阶段替代** | 复用既有 `PhaseReplacement` | 克己跳过弃牌阶段、裸衣询问摸牌阶段 |
| **目标转移** | `Liuli` 改写 `flow.targets` | 不取消原杀、不重建新杀，直接改当前结算的目标 |
| **观星** | `skill_state` + 牌堆读取 | 第一版：查看牌堆顶 N 张并报告（见"非阻断问题"） |
| **离间** | `UseCardAction` + 虚拟【决斗】 | 复用引擎的决斗结算，没有复制决斗代码 |

测试过程中发现并修复的三个真实问题：

1. **可变费用技能选不了牌**：`select_skill_cost_card` 与 `start_skill_activation` 都以 `cost_cards` 为准，`variable_cost` 技能（制衡 / 仁德）根本进不了选牌流程。已修。
2. **洛神访问不存在的路径**：`context.state.game` 不存在，真实对局一旦有甄姬就会崩。改用 `context.services["engine"].game`（与既有技能一致）。
3. **测试对随机武将分配的隐性依赖**：AI 随机分到诸葛亮且无手牌时，空城让【杀】的候选从 2 个降到 1 个，引擎随即自动选定目标，Phase 5 的目标点击测试就点不到面板了；另一处转换解绑测试用"PLAY 上下文匹配数"推断归属，在有响应-only 转换（倾国）的武将身上不成立。前者给测试 AI 发一张手牌（保持 25 人随机池），后者改为按 owner 精确统计归属。

## 10. 非阻断问题

1. **观星是简化版**：目前实现"准备阶段查看牌堆顶 N 张并报告内容"，**没有做重排交互 UI**。要完整实现需要一个新的通用 Pending（多选 + 排序）和对应面板。
2. **无双只覆盖【杀】**：`RESPONSE_COUNT` 目前只被 `ShaEffect` 消费；【决斗】的"需要两张【杀】"尚未接入（决斗流程需要同样的循环要牌改造）。
3. **流离自动选目标**：转移本身是"改当前结算目标"的正确做法，但选择哪个角色目前由代码取第一个合法角色，没有让玩家选。
4. **激将自动选同伴**：同理，没有做"逐个询问蜀势力角色"的交互链，直接取第一个持有【杀】的同伴。
5. **洛神只判定一次**：没有实现"可以继续判定直到红色或放弃"的循环。
6. **救援按标准版实现**：即"其他吴势力角色对你使用【桃】时额外回复 1 点"；若你采用的版本不同（如界孙权），行为需要调整。
7. **离间固定选前两名男性**：玩家只能选择"发起决斗的一方"，另一方按座次取第一个。
8. 前几个阶段记录的问题（骅骝缺素材、普通牌背缺失、iCCP 提示、第二批以外武将未加入）按要求本次未处理。
